## 1. 项目背景与目标

### 1.1 项目背景

随着「独立设计师品牌」的兴起，越来越多的设计师选择创建个人工作室，提供服装定制、手工皮具、数字插画等非标准化的个性化服务。然而，当前大多数独立工作室仍采用传统的作坊式管理模式：

- **依赖微信群沟通** - 信息碎片化，难以追溯
- **使用 Excel 表格排单** - 效率低，易出错
- **缺乏系统化管理** - 库存混乱，客户跟进困难

### 1.2 现有问题分析

| 问题类型 | 具体表现 | 解决方案 |
|---------|---------|---------|
| 信息孤岛 | 客户端与生产端数据不通 | 统一数据平台，打通双端 |
| 流程非标 | 不同品类定制需求差异大 | 动态表单引擎 + 可配置工作流 |
| 过程黑盒 | 客户无法实时查看进度 | WebSocket 实时推送 + 进度时间轴 |
| 库存管理混乱 | 物料进出库无记录 | 供应链模块 + BOM 管理 |
| 决策缺乏数据 | 凭经验做经营决策 | 数据分析 Dashboard |

### 1.3 系统目标

本项目旨在构建一个 **低代码生产管理平台**，实现以下目标：

1. **信息一体化** - 打通客户端（小程序）与生产端（Web后台）的数据链路
2. **流程可配置** - 通过动态表单引擎和工作流编排实现零代码扩展
3. **进度可视化** - 客户实时追踪，设计师高效管理
4. **决策数据化** - 多维度数据分析，辅助经营决策

### 1.4 项目边界

**包含范围：**
- 客户管理（CRM）
- 订单全生命周期管理
- 物料库存管理
- 在线实时沟通（IM）
- 进度可视化追踪
- 作品集内容管理
- 多品类动态模板配置
- 基础财务记录
- RBAC 权限控制

**不包含范围：**
- 详细财务报表与税务计算
- 员工薪酬（HR）管理
- 非定制化的标准电商功能
- 物流公司 API 对接
- APP 移动端（仅小程序 + Web）

## 2. 用户角色分析

### 2.1 角色总览

| 角色 | 端 | 数量 | 权限级别 |
|-----|-----|------|---------|
| 客户 | 小程序/Web | N | 只能查看/操作自己的数据 |
| 设计师 | Web 后台 | 1-5 | 查看/操作被指派的订单 |
| 管理员 | Web 后台 | 1-2 | 全部权限 |

### 2.2 客户 (Client)

**用户画像：**
- 追求个性化定制的消费者
- 对生产过程好奇但缺乏专业知识
- 习惯移动端碎片化操作

**使用端：**
- **小程序端**：浏览作品、提交定制需求、查看进度、在线沟通、确认收货、在线支付
- **Web 端**：适合需要上传大量参考图、详细描述需求的场景

**核心痛点：**
- 沟通成本高（反复描述需求）
- 无法实时把控进度
- 需求描述不准确

**功能需求：**
- 微信一键登录
- 个人档案管理（昵称、头像、手机号）
- 地址簿管理（最多10个）
- 业务通知接收
- 作品集浏览
- 定制需求提交
- 订单进度查看
- 在线支付/退款
- 即时通讯

### 2.3 设计师 (Designer)

**用户画像：**
- 工作室核心生产力
- 兼具客服与工匠职能
- 需同时处理多并发订单

**核心痛点：**
- 容易遗漏订单细节
- 被动响应进度查询占用时间
- 重复排单效率低

**功能需求：**
- 意向池管理（查看、处理客户意向）
- 订单看板（拖拽式生产管理）
- 订单详情操作（转单、进度更新、阻塞标记）
- BOM 配置
- 客户沟通
- 个人订单统计

### 2.4 系统管理员 (Admin)

**用户画像：**
- 工作室运营者
- 统筹全局
- 关心效率、成本和客户满意度

**核心痛点：**
- 库存管理混乱
- 缺乏数据看板
- 流程标准化困难

**功能需求：**
- 品类配置（新增、编辑、禁用业务品类）
- 动态字段配置（配置专属定制参数）
- 工作流编排（配置专属生产流程节点）
- 物料库维护
- 员工账号与权限管理
- 数据分析 Dashboard
- 系统监控与运维

### 5.5 库存与状态的并发控制（乐观锁）

为防止多线程并发场景下出现「超卖」或「脏数据」问题，采用 **乐观锁 (Optimistic Locking)** 机制：

```sql
-- 物料表增加版本号
ALTER TABLE ds_material ADD COLUMN version INT DEFAULT 0 COMMENT '版本号（乐观锁）';

-- 订单表增加版本号
ALTER TABLE ds_order ADD COLUMN version INT DEFAULT 0 COMMENT '版本号（乐观锁）';
```

**实现原理：**

```java
/**
 * 库存扣减 - 乐观锁实现
 */
public boolean deductStock(Long materialId, BigDecimal quantity) {
    // 1. 先查询当前库存和版本号
    DsMaterial material = mapper.selectById(materialId);
    BigDecimal currentStock = material.getStock();
    Integer currentVersion = material.getVersion();

    // 2. 校验库存是否充足
    if (currentStock.compareTo(quantity) < 0) {
        throw new BusinessException("库存不足", 50001);
    }

    // 3. 尝试更新（带版本号条件）
    int rows = mapper.updateStockWithVersion(materialId, quantity, currentVersion);
    if (rows == 0) {
        // 4. 更新失败，说明有并发冲突，重试
        return deductStock(materialId, quantity); // 递归重试（建议加最大重试次数）
    }
    return true;
}

@Update("UPDATE ds_material SET stock = stock - #{quantity}, " +
       "version = version + 1 WHERE material_id = #{materialId} " +
       "AND version = #{currentVersion} AND stock >= #{quantity}")
int updateStockWithVersion(@Param("materialId") Long materialId,
                          @Param("quantity") BigDecimal quantity,
                          @Param("currentVersion") Integer currentVersion);
```

### 5.6 财务模块的幂等性设计

为防止网络抖动导致「重复支付」或「重复退款」造成的资损，采用 **唯一流水号 + 数据库唯一索引** 双重保障：

```sql
-- 支付表增加微信流水号（唯一索引）
ALTER TABLE ds_payment_record ADD COLUMN out_trade_no VARCHAR(64) COMMENT '微信支付交易号';
ALTER TABLE ds_payment_record ADD UNIQUE INDEX uk_out_trade_no (out_trade_no);

-- 退款表增加微信退款号（唯一索引）
ALTER TABLE ds_refund_record ADD COLUMN out_refund_no VARCHAR(64) COMMENT '微信退款单号';
ALTER TABLE ds_refund_record ADD UNIQUE INDEX uk_out_refund_no (out_refund_no);

-- 支付时先查询是否已存在（防重复提交）
-- 退款时先查询原支付记录是否存在
```

**实现流程：**

```java
/**
 * 微信支付 - 幂等处理
 */
public String createPayment(PaymentDTO dto) {
    // 1. 生成内部流水号（唯一）
    String paymentNo = generatePaymentNo();

    // 2. 检查是否已存在（幂等）
    DsPaymentRecord exist = paymentMapper.selectByOrderIdAndType(
        dto.getOrderId(), dto.getPaymentType());
    if (exist != null) {
        // 已存在，直接返回已有流水号
        return exist.getPaymentNo();
    }

    // 3. 调用微信统一下单接口，获取 out_trade_no
    WxPayUnifiedOrderRequest request = new WxPayUnifiedOrderRequest();
    request.setOutTradeNo(paymentNo);
    // ... 其他参数
    WxPayUnifiedOrderResult wxResult = wxPayService.unifiedOrder(request);

    // 4. 创建支付记录（out_trade_no 唯一索引保护）
    DsPaymentRecord record = DsPaymentRecord.builder()
        .paymentNo(paymentNo)
        .outTradeNo(wxResult.getOutTradeNo()) // 微信返回的交易号
        .orderId(dto.getOrderId())
        .amount(dto.getAmount())
        .status(0) // 待支付
        .build();
    paymentMapper.insert(record);

    return paymentNo;
}

/**
 * 微信退款 - 幂等处理
 */
public void refund(RefundDTO dto) {
    // 1. 生成内部退款号
    String refundNo = generateRefundNo();

    // 2. 检查是否已退款（幂等）
    DsRefundRecord exist = refundMapper.selectByPaymentId(dto.getPaymentId());
    if (exist != null && exist.getStatus() == 1) {
        // 已退款成功，直接返回
        return;
    }

    // 3. 调用微信退款接口
    WxPayRefundRequest request = new WxPayRefundRequest();
    request.setOutRefundNo(refundNo);
    // ... 其他参数
    wxPayService.refund(request);

    // 4. 创建退款记录
    DsRefundRecord record = DsRefundRecord.builder()
        .refundNo(refundNo)
        .outRefundNo(wxResult.getOutRefundNo()) // 微信退款单号
        .paymentId(dto.getPaymentId())
        .refundAmount(dto.getRefundAmount())
        .status(0) // 处理中
        .build();
    refundMapper.insert(record);
}
```

```java
        }

        // 校验文件类型
        String contentType = file.getContentType();

        Path path = Paths.get(properties.getUploadPath(), fileName);
```

#### 5.8.3 Nginx 静态资源代理（关键！）

**绝对不能使用 Spring Boot 接口返回图片流**，必须配置 Nginx 静态代理：

```nginx
# /etc/nginx/conf.d/upload.conf

server {
    listen 80;
    server_name your-domain.com;

    # 静态资源目录映射（重要！）
    location /uploads/ {
        alias /data/uploads/;
        # 开启缓存
        expires 7d;
        # 开启 gzip 压缩
        gzip on;
        gzip_types image/jpeg image/png image/webp;
    }

    # 动态接口代理到 Spring Boot
    location /api/ {
        proxy_pass http://127.0.0.1:8080/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

**优化效果：**
- 图片请求**不经过 Java 后端**，直接由 Nginx 从磁盘读取
- 高并发下 Nginx 性能远超 Spring Boot
- 减轻后端线程消耗

```java
/**
 * 数据权限注解 - 控制查询数据范围
 * 作用于 Controller 方法或 Service 方法
 */
@Target({ElementType.METHOD, ElementType.TYPE})
@Retention(RetentionPolicy.RUNTIME)
public @interface DataScope {

    /**
     * 部门表别名（如订单表关联的部门字段）
     */
    String deptAlias() default "";

    /**
     * 用户表别名（如订单表的 designer_id）
     */
    String userAlias() default "";

    /**
     * 权限类型
     * - ALL: 全部数据
     * - DEPT: 本部门数据
     * - SELF: 仅自己的数据
     * - CUSTOM: 自定义数据范围
     */
    DataScopeType type() default DataScopeType.ALL;
}

public enum DataScopeType {
    ALL,       // 全部数据
    DEPT,      // 本部门数据
    SELF,      // 仅自己的数据
    CUSTOM     // 自定义（由角色配置）
}

/**
 * 字段级权限注解 - 控制返回字段是否脱敏
 */
@Target({ElementType.FIELD, ElementType.METHOD})
@Retention(RetentionPolicy.RUNTIME)
public @interface Sensitive {

    SensitiveStrategy strategy() default SensitiveStrategy.NONE;

    enum SensitiveStrategy {
        NONE,           // 不处理
        PHONE,          // 手机号：138****1234
        ID_CARD,        // 身份证：3201***********1234
        BANK_CARD,      // 银行卡：6222 **** **** 1234
        NAME            // 姓名：张*
    }
}
```

#### 7.1.5 权限控制设计

**7.1.5.1 权限模型总体设计**

采用 **RBAC + 数据权限** 双层权限模型：

```
┌─────────────────────────────────────────────────────────────────┐
│                        权限控制架构                               │
├─────────────────────────────────────────────────────────────────┤
│  第一层：功能权限 (Permission)                                   │
│  ├── 接口级别：@PreAuthorize 控制能否访问某个接口                │
│  ├── 按钮级别：前端根据权限标识控制按钮显示/隐藏                 │
│  └── 菜单级别：不同角色看到不同的菜单                            │
│                                                                 │
│  第二层：数据权限 (Data Scope)                                   │
│  ├── 行级权限：只能查看/操作自己范围内的数据                     │
│  ├── 字段权限：敏感字段脱敏或隐藏                                 │
│  └── 部门权限：只能查看本部门的数据                              │
└─────────────────────────────────────────────────────────────────┘
```

```java
/**
 * 权限服务接口
 */
public interface IPermissionService {

    /**
     * 获取当前用户的数据权限范围
     */
    DataScopeType getDataScope();

    /**
     * 获取当前用户能访问的部门ID列表
     */
    List<Long> getDataScopeDeptIds();

    /**
     * 校验用户是否有权访问指定订单
     */
    void checkOrderAccess(Long orderId);

    /**
     * 校验用户是否是订单负责人
     */
    void checkOrderOwner(Long orderId);

    /**
     * 过滤查询结果（加入数据权限条件）
     */
    <T> List<T> filterDataScope(List<T> records);
}

/**
 * 权限服务实现
 */
@Service
@RequiredArgsConstructor
public class PermissionServiceImpl implements IPermissionService {

    private final SysAdminMapper adminMapper;
    private final SysRoleMapper roleMapper;
    private final DsOrderMapper orderMapper;

    @Override
    public DataScopeType getDataScope() {
        LoginHelper loginHelper = LoginHelper.getInstance();
        if (loginHelper.isAdmin()) {
            return DataScopeType.ALL;
        }
        // 获取用户角色的最大数据范围
        return roleMapper.getMaxDataScope(loginHelper.getRoleIds());
    }

    @Override
    public void checkOrderAccess(Long orderId) {
        LoginHelper helper = LoginHelper.getInstance();

        // 管理员无限制
        if (helper.isAdmin()) {
            return;
        }

        DsOrder order = orderMapper.selectById(orderId);
        if (order == null) {
            throw new BusinessException("订单不存在", 30001);
        }

        // 客户：只能访问自己的订单
        if (helper.isClient()) {
            if (!order.getUserId().equals(helper.getUserId())) {
                throw new BusinessException("无权访问该订单", 20002);
            }
            return;
        }

        // 设计师：只能访问自己被指派的订单
        if (helper.isDesigner()) {
            if (!order.getDesignerId().equals(helper.getAdminId())) {
                throw new BusinessException("无权操作该订单", 20002);
            }
            return;
        }
    }

    @Override
    public void checkOrderOwner(Long orderId) {
        LoginHelper helper = LoginHelper.getInstance();
        if (helper.isAdmin()) {
            return;
        }

        DsOrder order = orderMapper.selectById(orderId);
        if (!order.getDesignerId().equals(helper.getAdminId())) {
            throw new BusinessException("只能操作自己被指派的订单", 20002);
        }
    }
}
```

```java
/**
 * 安全配置
 */
@Configuration
@EnableWebSecurity
@EnableMethodSecurity(prePostEnabled = true)
@RequiredArgsConstructor
public class SecurityConfig {

    private final JwtAuthenticationFilter jwtFilter;
    private final JwtAuthenticationEntryPoint entryPoint;

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) {
        http
            .csrf(AbstractHttpConfigurer::disable)
            .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                // 公开接口
                .requestMatchers("/api/v1/auth/**", "/api/v1/categories", "/api/v1/portfolios").permitAll()
                // 小程序接口需要 Token
                .requestMatchers("/api/v1/**").authenticated()
                // 后台接口需要角色
                .requestMatchers("/api/v1/admin/**").hasAnyRole("ADMIN", "DESIGNER")
                .anyRequest().authenticated()
            )
            .addFilterBefore(jwtFilter, UsernamePasswordAuthenticationFilter.class)
            .exceptionHandling(e -> e.authenticationEntryPoint(entryPoint));

        return http.build();
    }
}
```

```java
     * 订单看板 - 根据当前用户返回不同数据

     * 订单详情 - 校验访问权限
     */

    @PreAuthorize("@ss.hasPermission('order:detail')")
    @Operation(summary = "获取订单详情")
    public R<OrderDetailVO> getDetail(@PathVariable Long id) {
        // 数据权限校验
        permissionService.checkOrderAccess(id);
        return R.ok(orderService.getOrderDetail(id));
    }

    /**
     * 分配设计师 - 仅管理员可操作
     */
    @PutMapping("/{id}/assign")
    @PreAuthorize("@ss.isAdmin()")
    @Operation(summary = "分配设计师")
    public R<Void> assignDesigner(@PathVariable Long id,
                                  @RequestBody AssignDesignerDTO dto) {
        orderService.assignDesigner(id, dto.getDesignerId());
        return R.ok();
    }

     * 更新进度 - 只能更新自己被指派的订单
     */
    @PostMapping("/{id}/progress")
```

### 附录 A: 技术选型辩护词

> **为什么选择 Spring Boot + MyBatis-Plus？**
> Spring Boot 是当前 Java 后端开发的事实标准，具有「约定优于配置」的特性，能快速搭建生产级应用。MyBatis-Plus 在 MyBatis 基础上增加了通用 CRUD 和代码生成能力，减少重复代码的同时保留了对 SQL 的完全控制，适合本项目对复杂 JOIN 查询和动态条件的需求。

> **为什么选择 Vue 3 + Naive UI？**
> Vue 3 的 Composition API 提供了更灵活的逻辑复用方式。Naive UI 是新一代高颜值 Vue 3 组件库，设计感强、动画细腻，非常适合设计师类产品的后台界面。

> **为什么选择 Uni-app 开发小程序？**
> Uni-app 使用 Vue 语法开发小程序，降低了全栈开发的认知负荷，并具备跨平台能力，为未来扩展到其他小程序平台或 App 预留了可能。

### 附录 B: 核心概念解释

|-----|------|

| EAV (Entity-Attribute-Value) | 实体-属性-值模式，用于支持动态表单数据的数据库设计模式 |
