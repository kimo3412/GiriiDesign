# 后台全模块验收与小程序代码检查

生成日期：2026-05-06

本文档用于交给人工测试或其他 AI 继续执行验收。目标不是证明每个样式细节完美，而是确认后台与小程序没有阻挡系统主要功能流转的 bug。

## 1. 验收目标

- 后台 Web 管理端：按菜单逐项验证页面可进入、数据可加载、核心按钮可点击、关键业务状态能正常流转。

- 小程序：本次只做代码检查和构建检查，不做微信开发者工具真机/模拟器点击测试。

## 4. 关键业务主流程验收

建议按下面顺序执行一次完整链路：

1. 后台配置品类、字段、工作流、BOM。
2. 后台配置物料库存，确保 BOM 所需物料库存充足。
3. 小程序提交定制意向。
4. 后台意向管理审核并转订单。
5. 小程序支付定金。
6. 后台订单进入生产，工作台填写节点产出并推进。
7. 中途测试一次阻塞和解除阻塞。
8. 继续推进到完工。
9. 如果有尾款，小程序支付尾款。
10. 后台发货。
11. 小程序确认收货。
12. 后台数据分析、订单列表、客户详情、库存记录均能看到结果。

通过标准：

- 任意一步失败时，订单/意向/库存不能进入半更新状态。
- 页面刷新后状态一致。
- 小程序和后台看到的订单状态一致。

## 5. 并发与重复点击专项验收

这些是最容易影响系统流转的点，必须测：

1. 同一订单打开两个后台详情页。
2. 页面 A 推进节点成功。
3. 页面 B 不刷新，继续推进。
4. 页面 B 应失败，并提示订单状态已变化或请刷新。
5. 同一个推进按钮连续快速点击两次。
6. 订单最多只推进一步。
7. 同一意向连续点击两次转订单。
8. 最多只生成一个订单。
9. 同一物料库存被订单扣减或释放时，更新失败不能提示成功。

### 6.2 小程序主流程判断

登录流程：

- 微信登录走 `/api/v1/app/auth/wx-login`。
- 账号测试登录走 `/api/v1/app/auth/mock-login`。
- 登录成功后保存 token 和用户信息。
- 新用户会进入资料完善页，老用户进入首页。

首页流程：

- Banner 走公开接口。
- 作品集列表走公开接口。
- 首页能跳转到定制分类、聊天、订单、作品集。

定制意向流程：

- 分类列表走 `/api/v1/app/public/config/categories`。
- 动态字段走 `/api/v1/app/public/config/categories/{categoryId}/fields`。
- 提交意向走 `/api/v1/app/requests`。
- 提交后跳转订单列表。

订单流程：

- 订单列表走 `/api/v1/app/orders/my`。
- 订单详情走 `/api/v1/app/orders/{id}` 和 `/api/v1/app/orders/{id}/timeline`。
- 支付走 `/api/v1/app/orders/{id}/pay`。
- 确认收货走 `/api/v1/app/orders/{id}/confirm`。

用户与地址流程：

- 用户信息走 `/api/v1/app/auth/info` 和 `/api/v1/app/auth/update`。
- 地址增删改查走 `/api/v1/app/address` 相关接口。

通知流程：

- 通知列表、未读数、标记已读、全部已读都有对应接口。

聊天流程：

- 历史消息走 `/api/v1/app/chat`。
- WebSocket 地址为 `ws://localhost:8081/ws/chat?token=...`。
- 图片/文件上传走 `/api/v1/oss/chat-upload`。

结论：

- 从代码和构建结果看，小程序没有发现会阻挡登录、提交意向、查看订单、支付、确认收货、聊天、地址管理这些主流程运行的明确 bug。

### 6.3 小程序非阻塞风险

这些问题不一定阻挡系统功能流转，但建议测试者知道：

1. 定制表单中的图片字段和参考图看起来直接保存了本地临时路径，未在提交前统一调用上传接口。结果可能是：意向能提交，但后台或其他设备无法长期查看这些图片。
2. 作品集列表的品类筛选如果使用了硬编码品类 ID，当后台品类 ID 变化时，筛选结果可能不准确。
3. 小程序提交意向后跳转订单列表，但意向必须由后台审核转单后才会变成订单。因此刚提交后订单列表为空是业务预期，不是必然 bug。
4. `utils/request.js` 在 token 过期时会跳转登录页。源码中文显示乱码，但构建通过；乱码目前不是运行阻塞，只是维护体验差。
