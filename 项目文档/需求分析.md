# 独立设计师工作室生产流程管理系统 - 需求规格说明书 (SRS)

> [!NOTE]
> **毕设导师点评**:
> 本文档对应论文 **第三章 需求分析**。内容架构为：引言 -> 用户分析 -> 功能需求(6大子系统) -> 核心用例 -> 非功能需求 -> 系统亮点。
> 核心技术栈：**Spring Boot + MyBatis-Plus + Redis + MySQL + Vue 3 + 微信小程序**（纯手写，无任何脚手架依赖）。

---

## 1. 引言 (Introduction)

### 1.1 编写目的
本文档旨在详尽定义"独立设计师工作室生产流程管理系统"的全部功能与非功能需求，明确系统边界与行为规范。本文档将作为后续系统设计、编码实现及测试的**唯一基准**。

### 1.2 项目背景
随着"独立设计师品牌"的兴起，传统的作坊式管理（依赖微信沟通、Excel排单）已成为制约工作室规模化的瓶颈。目前市场上的ERP系统多为标准化电商或大型工厂设计，无法满足独立工作室 **"非标定制、强沟通、长周期"** 的生产特点。

### 1.3 系统目标
本项目旨在构建一个基于 **Spring Boot** 的 **模块化单体系统**，解决以下核心痛点：
1.  **信息孤岛**：打通客户端（小程序）与生产端（Web后台）的数据链路。
2.  **流程非标**：通过 **动态表单引擎** 实现不同品类（如服装 vs 插画）的定制需求差异化。
3.  **过程黑盒**：通过 **可配置状态机** 实现生产过程的可视化追踪。

### 1.4 术语定义 (Glossary)
| 术语 | 定义 |
| :--- | :--- |
| **BOM (Bill of Materials)** | 物料清单。指生产一件定制产品所需的所有原材料及其数量。 |
| **EAV (Entity-Attribute-Value)** | 实体-属性-值模式。用于支持动态表单数据的数据库设计模式。 |
| **FSM (Finite State Machine)** | 有限状态机。用于描述订单在不同生命周期间的流转规则。 |
| **动态表单 (Dynamic Form)** | 表单字段根据后台配置的 JSON Schema 实时渲染，而非硬编码。 |

### 1.5 系统范围
*   **包含**: 客户管理(CRM)、订单全生命周期管理、物料库存管理、在线实时沟通(IM)、进度可视化追踪、作品集内容管理、多品类动态模板配置、基础财务记录、RBAC权限控制。
*   **不包含**: 详细财务报表与税务、员工薪酬(HR)管理、非定制化的标准电商(B2C)功能、物流公司API对接。

## 2. 用户角色分析 (User Analysis)

### 2.1 客户 (Client) - [小程序端 + Web端]
*   **画像**: 追求个性化，对生产过程好奇但缺乏专业知识，习惯移动端碎片化操作。
*   **多端场景**:
    *   **小程序端**：浏览作品、提交定制需求、查看实时进度、在线沟通、确认收货与评价、在线支付。
    *   **Web端**：适合需要上传大量参考图、详细描述需求的场景，提供更完整的交互体验。
*   **核心痛点**: 沟通成本高、无法实时把控进度、需求描述不准确。

### 2.2 设计师 (Designer) - [Web后台]
*   **画像**: 工作室核心生产力，兼具客服与工匠职能。需同时处理多并发订单。
*   **核心痛点**: 容易遗漏订单细节、被动响应进度查询占用时间、重复排单效率低。
*   **核心场景**: 评估意向、转正订单、配置BOM、按节点更新生产进度、回复客户消息。

### 2.3 系统管理员 (Admin) - [Web后台]
*   **画像**: 工作室的运营者，统筹全局，关心效率、成本和客户满意度。
*   **核心痛点**: 库存管理混乱、缺乏数据看板、流程标准化困难。
*   **核心场景**: 品类与动态表单配置、工作流模板配置、物料库维护、员工账号与权限管理。

## 4. 核心业务用例详述 (Key Use Cases)

### UC-01: 客户提交动态定制意向
*   **参与者**: 客户 (Client)
*   **前置条件**: 客户已授权登录微信小程序。
*   **基本流程**:
    1.  客户进入"发起定制"页面。
    2.  系统调用 `GET /api/category/listActive` 加载品类列表。
    3.  客户选择品类（如：服装）。
    4.  系统调用 `GET /api/category/{categoryId}/schema` **动态拉取表单定义 (JSON Schema)**。
    5.  前端根据 Schema 渲染表单控件（如：数字输入框"胸围"、下拉框"风格"）。
    6.  客户填写数据、上传参考图。
    7.  客户点击"提交"。
    8.  系统调用 `POST /api/request`，将数据存入 `ds_order_request` 表。
*   **异常流程**:
    *   E1: 必填项未填 -> 前端校验拦截。
    *   E2: 图片上传失败 -> 提示重试。

### UC-02: 设计师转化意向为正式订单
*   **参与者**: 设计师 (Designer)
*   **前置条件**: 存在 `status=0` (待处理) 的意向。
*   **基本流程**:
    1.  设计师打开"意向池"。
    2.  点击某条意向进入详情。
    3.  评估可行性后，点击"受理"。
    4.  弹出表单：填写 `预估工期`、`总价`、`预付款金额`，选择 `指派设计师`。
    5.  系统执行事务：
        a. 创建 `ds_order` 记录。
        b. 根据 `category_id` 查询 `ds_workflow`，获取初始 `step_id`，写入订单。
        c. 将定制参数 JSON 快照到 `ds_order.custom_data_snapshot`。
        d. 更新 `ds_order_request.status = 1 (已转单)`。
    6.  (可选) 发送微信订阅消息通知客户。
*   **后置条件**: 订单出现在看板的第一列。

### UC-03: 生产节点推进与进度汇报
*   **参与者**: 设计师 (Designer)
*   **逻辑规则**: 必须严格按 `ds_workflow_step.step_order` 顺序推进，不可跳跃。
*   **基本流程**:
    1.  设计师在看板中拖拽订单卡片至下一列，或在订单详情页点击"推进到下一步"。
    2.  系统校验目标 `step_id` 是否为当前 `step_id` 的合法后继。
    3.  弹出进度汇报表单：填写描述（可选）、上传图片（可选）。
    4.  系统执行事务：
        a. 更新 `ds_order.current_step_id`。
        b. 插入一条 `ds_order_progress` 记录。
    5.  小程序端用户实时可见新进度。
*   **异常流程**:
    *   E1: 尝试跳跃节点 -> 后端校验失败，返回错误提示"当前节点无法直接跳转到目标节点"。

### UC-04: 库存锁定与BOM出库
*   **参与者**: 设计师/管理员
*   **逻辑规则**: 库存扣减发生在"订单进入生产阶段"时，而非下单时。
*   **基本流程**:
    1.  订单转正后，设计师为其配置 BOM 清单。
    2.  订单状态推进至"生产中"(如：第一个生产节点)。
    3.  系统自动触发库存锁定检查：遍历 BOM，判断各物料库存是否充足。
    4.  若充足，执行 `UPDATE ds_material SET stock = stock - #{qty}`。
    5.  若不足，抛出警告，订单可标记为"阻塞-缺料"。

## 5. 非功能需求 (Non-Functional Requirements)

### 5.1 性能需求 (Performance)
| 指标 | 目标值 | 备注 |
| :--- | :--- | :--- |
| API 平均响应时间 | < 500ms | 核心查询接口 |
| 小程序首屏加载 | < 2s | 需使用图片懒加载、CDN |
| 看板页面渲染 | < 1s | 订单量 < 500 时 |
| WebSocket 消息延迟 | < 200ms | 同城网络环境 |

### 5.2 安全需求 (Security)
| 需求项 | 描述 |
| :--- | :--- |
| 接口鉴权 | C端：JWT + 微信 session_key；B端：JWT + Spring Security。 |
| 数据隔离 | 设计师角色只能查看/操作自己被指派的订单。 |
| 敏感数据 | 密码使用 BCrypt 加密存储；客户手机号、地址需脱敏展示。 |
| 越权防护 | 所有接口必须校验当前用户是否有权操作目标资源。 |
| 传输安全 | 全站 HTTPS。 |

### 5.3 可用性需求 (Usability)
*   小程序端符合微信设计规范，核心操作路径清晰（3步内完成提交）。
*   后台管理端界面简洁，常用功能（更新进度、回复消息）置于显眼位置。

### 5.4 可扩展性需求 (Extensibility)
*   数据库设计预留 `tenant_id` 字段，为未来 SaaS 多商户模式做准备（可选实现）。
*   动态表单引擎设计通用，新增品类无需修改代码。

## 6. 系统亮点与工作量评估 (Highlights & Workload)

### 6.1 技术亮点与创新总结

> [!IMPORTANT]
> **答辩核心陈述**：本系统定位为"**面向独立设计师的低代码生产管理平台**"，三大核心创新如下。

#### 创新点一：低代码业务扩展引擎
*   **技术实现**：动态表单引擎 (EAV Hybrid Pattern) + 可视化工作流编排。
*   **核心价值**：管理员**无需编程知识**，通过后台配置界面即可：
    1.  定义新的业务品类（如：从服装扩展到文创产品）
    2.  配置每个品类专属的定制参数表单（字段类型、校验规则）
    3.  编排专属的生产流程节点（如：文创产品"设计→打样→量产→发货"）
*   **学术意义**：实现了"**流程即配置、表单即配置**"的低代码理念，系统具备零代码扩展能力。

#### 创新点二：多维度生产效能分析与决策支持
*   **技术实现**：基于 ECharts 的可视化 Dashboard + 统计型 SQL 聚合查询。
*   **核心指标**：
    | 分析维度 | 关键指标 | 决策支持 |
    | :--- | :--- | :--- |
    | 订单概览 | 本月订单数、成交额、转化率 | 经营健康度评估 |
    | 设计师效率 | 人均订单数、平均完成天数、驳回率 | 人员绩效考核 |
    | 库存周转 | 物料使用频率、呆滞物料、缺货预警 | 采购决策优化 |
    | 客户画像 | 消费频次、偏好品类、复购率 | 精准营销 |
*   **学术意义**：将系统从"**数据记录工具**"升级为"**数据决策平台**"，体现信息系统的商业价值。

#### 创新点三：全链路实时协同与进度可视化
*   **技术实现**：WebSocket 双向通讯 + 拖拽式看板 + 时间轴组件。
*   **核心价值**：
    1.  客户端：实时追踪订单进度，时间轴展示生产里程碑。
    2.  设计师端：通过拖拽看板高效管理多订单，一屏掌握全局。
    3.  即时沟通：订单内嵌聊天，消息秒级送达，减少沟通成本。
*   **学术意义**：体现现代 Web 应用的**实时性**与**交互体验**。
